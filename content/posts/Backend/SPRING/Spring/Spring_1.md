# 1. Spirng 필요 

- Java 기반의 오픈소스 애플리케이션 프레임워크 
- 엔터프라이즈급 애플케이션 개발을 위한 표준 프레임워크
- 복잡한 자바 개발을 단순화하는 컨테이너 역할 

| 특징 | 설명 | 쉽게 말하면 |
|---|---|---|
| 경량 프레임워크 | 필요한 모듈만 선택해 사용하므로 메모리 부담이 적음 | 필요한 기능만 골라 사용 |
| 제어의 역전(IoC) | 객체의 생성과 관리를 개발자가 아닌 프레임워크가 담당 | 프레임워크가 객체를 관리 |
| 의존성 주입(DI) | 객체 간 결합도를 낮춰 유지보수성을 높임 | 필요한 객체를 외부에서 주입 |
| 관점 지향 프로그래밍(AOP) | 로깅, 보안, 트랜잭션 같은 공통 기능을 분리 | 반복 코드를 한곳에서 관리 |
| 모듈화 | Web, Data, Security 등 기능을 모듈별로 관리 | 기능을 나누어 관리 |
| 확장성 | 오픈소스 기반으로 다양한 확장 프로젝트와 연동 가능 | 필요한 기능을 쉽게 추가 |
| 테스트 용이성 | DI와 Mock 객체를 활용해 단위 테스트를 쉽게 작성 | 실제 객체 없이도 테스트 가능 |

# Spring의 역사 

Spring: 복잡한 Java EE의 대안 à 유연하고 강력한 자바 엔터프라이즈 개발 프레임워크

Spring Boot: 쉽게, 빠르게 Spring을! à 설정 최소화, 스타트업/대기업 모두 사랑하는 표준 플랫폼으로 발전

| 구분 | Spring | Spring Boot |
|---|---|---|
| 등장 | 2003년, 1.0 | 2014년, 1.0 |
| 목적 | 유연하고 강력한 엔터프라이즈 애플리케이션 개발 | 빠르고 쉬운 Spring 개발, 복잡한 설정 최소화 |
| 주요 특징 | IoC/DI, AOP, 다양한 모듈 | 자동 설정, 스타터, 내장 서버, 간편한 실행 |

# Spring Boot의 등장 배경 

### Spring과 Spring Boot

전통적인 Spring 개발은 XML 설정 파일과 다양한 환경 설정을 직접 작성해야 했기 때문에 프로젝트 초기 구성에 많은 시간이 필요함

신규 프로젝트를 빠르게 개발하고 배포하려면 반복적이고 필수적인 설정을 자동화할 필요

이러한 불편을 해결하고 Spring을 더 쉽고 빠르게 사용할 수 있도록 Spring Boot가 등장

| 구분 | Spring | Spring Boot |
|---|---|---|
| 설정 방식 | XML과 설정 파일을 직접 구성 | 자동 설정을 통해 복잡한 설정을 최소화 |
| 개발 시작 | 초기 환경 구축에 시간이 필요 | 프로젝트를 빠르게 생성하고 실행 |
| 개발 목표 | 유연하고 세밀한 애플리케이션 구성 | Spring 개발의 편의성과 생산성 향상 |

### Spring Boot의 특징

| 특징 | 설명 | 쉽게 말하면 |
|---|---|---|
| 자동 설정(Auto-configuration) | 현재 환경과 추가된 라이브러리를 감지해 필요한 설정을 자동으로 적용 | 개발자가 설정하지 않아도 Spring Boot가 알맞은 기본 설정을 해줌 |
| 내장 서버 지원 | Tomcat, Netty 등의 서버를 별도로 설치하지 않아도 JAR 파일로 실행 가능 | 서버를 따로 준비하지 않고 애플리케이션 자체를 바로 실행할 수 있음 |
| Starter에 의한 의존성 관리 | 프로젝트 목적에 맞는 기본 라이브러리 묶음을 Starter로 한 번에 추가 | 웹 개발에 필요한 라이브러리를 하나씩 찾지 않고 세트로 설치 |
| 복잡한 XML 설정 최소화 | 어노테이션과 YAML 또는 Properties 파일을 사용해 간단하게 설정 | 긴 XML 파일 대신 간단한 코드와 설정 파일로 관리 |
| 운영 및 모니터링 용이 | 헬스 체크, 메트릭스 등 애플리케이션 상태를 확인하는 기능 제공 | 서버가 정상적으로 실행 중인지 쉽게 확인할 수 있음 |
| 쉬운 배포 | 빌드한 JAR 파일을 실행하거나 Docker 등 다양한 환경에 배포 가능 | `java -jar` 명령어만으로 애플리케이션을 실행할 수 있음 |


## 참고) 전통적인 Spring vs Spring Boot

| 비교 항목 | 전통적 Spring | Spring Boot |
|---|---|---|
| 서버 동작 방식 | 외부 WAS(WebSphere, WebLogic, JEUS 등)를 항상 실행하고 WAR로 배포 | 내장 서버(Tomcat, Jetty, Undertow, Netty 등)를 포함해 JAR로 실행 |
| 아키텍처 스타일 | MVC(Model-View-Controller) 중심 | REST API와 Model 중심 |
| 패키징 | WAR 형식이 일반적 | JAR 형식이 기본 |
| 설정 방식 | XML 또는 Java Config 중심, 수동 설정이 많음 | 자동 설정(Auto-Configuration), Starter 의존성 제공 |
| 배포 방식 | WAS에 수동 배포<br>`cp target/myapp.war TOMCAT_HOME/webapps/` | JAR 파일을 명령어로 바로 실행<br>`java -jar myapp.jar` |
| 실행 환경 | 별도의 WAS 설치 필요 | 내장 서버 기반으로 별도 WAS 설치 불필요 |
| 서버 교체 | WAS 설정을 변경해야 함 | 관련 의존성 변경만으로 서버 교체 가능 |
| 시작 속도 | 상대적으로 느림 | 상대적으로 빠름 |
| 사용 편의성 | 초기 설정이 복잡함 | 설정이 간단하고 빠른 개발 가능 |
