# DFS와 BFS

그래프나 격자(미로)를 탐색할 때 가장 많이 쓰는 알고리즘은 DFS(깊이 우선 탐색)와 BFS(너비 우선 탐색)이다.

- **DFS (Depth-First Search)**: 한 방향으로 갈 수 있을 때까지 깊게 들어간 뒤, 더 갈 곳이 없으면 되돌아온다.
- **BFS (Breadth-First Search)**: 시작점에서 가까운 정점부터, 같은 거리끼리 차례대로 탐색한다.

아래 그래프로 두 알고리즘의 동작을 살펴보자. 인접 노드는 리스트에 적힌 순서대로 확인한다.

~~~python
graph = {
    1: [2, 3],
    2: [4],
    3: [4],
    4: []
}
~~~

~~~text
1 ──> 2 ──> 4
│             ^
└──> 3 ──────┘
~~~

## 방문 처리

그래프에는 1 -> 2 -> 1처럼 다시 돌아오는 길(사이클)이 있을 수 있다. 방문 기록이 없으면 같은 정점을 계속 방문할 수 있으므로, 이미 탐색한 정점은 반드시 기록한다.

~~~python
visited = set()
~~~

파이썬의 set은 특정 값이 있는지 빠르게 확인할 수 있어 방문 여부를 관리하는 데 적합하다.

---

## DFS: 깊이 우선 탐색

DFS는 현재 정점에서 갈 수 있는 첫 번째 정점으로 계속 이동한다. 막다른 길에 도착하면 이전 갈림길로 돌아와 아직 탐색하지 않은 길을 선택한다.

### 재귀로 구현하기

재귀 함수 호출은 호출 스택에 쌓이므로 DFS를 간단하게 구현할 수 있다.

~~~python
graph = {
    1: [2, 3],
    2: [4],
    3: [4],
    4: []
}

visited = set()

def dfs(node):
    visited.add(node)        # 현재 정점을 방문 처리
    print(node, end=" ")     # 현재 정점 처리

    for next_node in graph[node]:
        if next_node not in visited:
            dfs(next_node)  # 방문하지 않은 곳으로 더 깊게 이동

dfs(1)
# 1 2 4 3
~~~

### 실제 탐색 과정

|순서|현재 정점|동작|방문한 정점|
|---:|---:|---|---|
|1|1|1을 방문한 뒤 첫 번째 이웃 2로 이동|{1}|
|2|2|2를 방문한 뒤 이웃 4로 이동|{1, 2}|
|3|4|4를 방문. 더 갈 곳이 없어 이전 호출로 돌아감|{1, 2, 4}|
|4|1|2의 탐색이 끝났으므로 다음 이웃 3으로 이동|{1, 2, 4}|
|5|3|3을 방문. 이웃 4는 이미 방문했으므로 종료|{1, 2, 3, 4}|

따라서 탐색 순서는 **1 -> 2 -> 4 -> 3**이다. DFS는 2를 선택한 뒤 4까지 먼저 내려가고, 그 다음에야 3을 탐색한다.

### 스택으로 구현하기

재귀 호출이 너무 깊어질 수 있거나 동작을 직접 제어하고 싶다면 스택을 사용한다. 스택은 마지막에 넣은 값을 먼저 꺼내는 LIFO(Last In, First Out) 구조다.

~~~python
def dfs_stack(start):
    visited = set()
    stack = [start]

    while stack:
        node = stack.pop()

        if node in visited:
            continue

        visited.add(node)
        print(node, end=" ")

        # 역순으로 넣으면 재귀 DFS와 같은 순서를 만들 수 있다.
        for next_node in reversed(graph[node]):
            if next_node not in visited:
                stack.append(next_node)

dfs_stack(1)
# 1 2 4 3
~~~

1의 이웃 [2, 3]을 스택에 그대로 넣으면 3이 먼저 꺼내진다. 따라서 재귀 DFS처럼 2를 먼저 방문하고 싶다면 [3, 2] 순서로 넣어야 하므로 reversed를 사용한다.

## DFS 예제: 숫자마다 + 또는 -를 선택해 target 만들기

각 숫자 앞에 + 또는 -를 붙여 target을 만드는 경우의 수를 구하는 문제다. 숫자 하나마다 선택지가 2개이므로, DFS는 모든 부호 선택을 하나의 이진 트리처럼 탐색한다.

~~~python
def solution(numbers, target):
    answer = 0

    # i: 현재 처리할 숫자의 인덱스
    # current_sum: i번째 숫자 전까지 선택한 부호의 누적합
    def dfs(i, current_sum):
        nonlocal answer

        # 모든 숫자를 사용했다면 target을 만들었는지 확인한다.
        if i == len(numbers):
            if current_sum == target:
                answer += 1
            return

        # i번째 숫자에 +를 붙이는 경우
        dfs(i + 1, current_sum + numbers[i])

        # i번째 숫자에 -를 붙이는 경우
        dfs(i + 1, current_sum - numbers[i])

    dfs(0, 0)
    return answer
~~~

예를 들어 numbers가 [1, 1, 1, 1, 1]이고 target이 3이라면, DFS는 첫 번째 숫자부터 +1 또는 -1을 각각 선택하며 모든 경우를 탐색한다.

~~~text
dfs(0, 0)
├─ +1 선택 -> dfs(1, 1)
│  ├─ +1 선택 -> dfs(2, 2)
│  │  └─ ... 마지막 숫자까지 선택
│  └─ -1 선택 -> dfs(2, 0)
└─ -1 선택 -> dfs(1, -1)
   ├─ +1 선택 -> dfs(2, 0)
   └─ -1 선택 -> dfs(2, -2)
~~~

마지막 인덱스에 도달한 경우에만 누적합을 target과 비교한다. 이 예시의 반환값은 5이며, 이는 + 부호를 4개, - 부호를 1개 붙이는 위치가 5가지이기 때문이다.

- 숫자가 N개면 가능한 부호 조합은 2^N개다.
- 시간 복잡도는 O(2^N)이다.
- 재귀 호출의 최대 깊이는 숫자 개수 N이므로, 탐색 스택은 O(N) 메모리를 사용한다.
- answer는 바깥 함수의 변수이므로 내부 dfs에서 값을 바꾸려면 nonlocal 선언이 필요하다.

## BFS: 너비 우선 탐색

BFS는 한 정점의 이웃을 모두 확인한 뒤, 그 이웃들의 다음 이웃을 확인한다. 시작점에서 거리가 1인 정점, 거리 2인 정점, 거리 3인 정점 순으로 퍼져 나가는 방식이다.

### 큐로 구현하기

큐는 먼저 넣은 값을 먼저 꺼내는 FIFO(First In, First Out) 구조다. 파이썬에서는 앞에서 원소를 효율적으로 꺼낼 수 있는 deque를 사용한다.

~~~python
from collections import deque

graph = {
    1: [2, 3],
    2: [4],
    3: [4],
    4: []
}

def bfs(start):
    visited = {start}
    queue = deque([start])

    while queue:
        node = queue.popleft()  # 가장 먼저 들어온 정점을 꺼냄
        print(node, end=" ")

        for next_node in graph[node]:
            if next_node not in visited:
                visited.add(next_node)  # 큐에 넣는 순간 방문 처리
                queue.append(next_node)

bfs(1)
# 1 2 3 4
~~~

### 실제 탐색 과정

|순서|꺼낸 정점|큐의 변화|방문한 정점|
|---:|---:|---|---|
|시작|-|[1]|{1}|
|1|1|2, 3 추가 -> [2, 3]|{1, 2, 3}|
|2|2|4 추가 -> [3, 4]|{1, 2, 3, 4}|
|3|3|4는 이미 방문 -> [4]|{1, 2, 3, 4}|
|4|4|이웃이 없음 -> []|{1, 2, 3, 4}|

따라서 방문 순서는 **1 -> 2 -> 3 -> 4**이다. BFS는 2에서 4로 깊게 들어가기 전에, 1과 같은 거리에 있는 3을 먼저 처리한다.

> BFS에서는 정점을 **큐에 넣는 순간** 방문 처리하는 것이 중요하다. 꺼낼 때 방문 처리하면 여러 정점이 같은 정점을 중복해서 큐에 넣을 수 있다.

---

## DFS와 BFS 비교

|구분|DFS|BFS|
|---|---|---|
|탐색 방식|한 경로를 끝까지 탐색 후 되돌아감|가까운 정점부터 한 단계씩 탐색|
|주요 자료구조|재귀 호출 스택 또는 stack|큐(deque)|
|최단 거리 보장|보장하지 않음|모든 간선 비용이 같을 때 보장|
|시간 복잡도|O(V + E)|O(V + E)|
|추가 메모리 복잡도|O(V)|O(V)|

V는 정점(노드)의 개수, E는 간선(연결)의 개수다.

---

## 메모리 사용 관점에서의 차이

두 알고리즘 모두 방문 여부를 기록하면 visited에 최대 V개의 정점이 저장되므로, 최악의 경우 추가 메모리는 모두 O(V)이다. 다만 **어느 자료구조에 정점이 한꺼번에 쌓이는지**가 다르다.

### DFS의 메모리

DFS는 현재 탐색 중인 한 경로와 아직 처리하지 않은 분기점을 스택에 저장한다.

- 길게 이어진 그래프에서는 현재 경로의 길이만큼만 쌓인다.
- 예를 들어 1 -> 2 -> 3 -> ... -> N처럼 한 줄인 그래프라면 호출 스택은 최대 N개가 된다.
- 일반적으로 그래프의 최대 깊이를 H라고 하면, 탐색용 스택은 O(H)라고 볼 수 있다.
- 재귀 DFS는 파이썬의 재귀 깊이 제한에 걸릴 수 있다. 노드가 매우 많은 문제에서는 반복문 + 명시적 stack 구현이 더 안전하다.

~~~python
# 깊이가 매우 깊을 수 있다면 재귀보다 스택 DFS를 고려한다.
stack = [start]
~~~

### BFS의 메모리

BFS는 현재 거리의 정점들과 다음 거리의 정점들을 큐에 보관한다.

- 한 단계에 이웃 정점이 많이 퍼지는 그래프일수록 큐가 커진다.
- 루트에서 자식이 많이 갈라지는 트리에서는 가장 아래 층의 정점들이 한꺼번에 큐에 들어갈 수 있다.
- 따라서 최단 거리는 BFS로 쉽게 구할 수 있지만, 넓은 격자나 많은 분기가 있는 그래프에서는 DFS보다 메모리를 많이 사용할 수 있다.

~~~text
DFS: 한 경로를 깊게 유지한다.
BFS: 같은 거리의 여러 정점을 동시에 유지한다.
~~~

### 격자 문제의 실전 팁

N x M 격자를 탐색할 때 방문 배열을 별도로 만들면 O(N x M)의 메모리가 추가로 필요하다. 입력 grid 자체를 방문 처리용으로 바꿔도 괜찮은 문제라면, 아래처럼 원본 값을 변경해 별도 visited 배열을 줄일 수 있다.

~~~python
grid[nr][nc] = 0  # 방문한 길을 막힌 칸으로 변경
~~~

단, 탐색 뒤에도 원본 grid가 필요하거나 입력을 보존해야 한다면 별도의 visited 배열을 사용해야 한다.

## 문제에서 어떤 단서가 나오면 사용할까?

### DFS를 떠올릴 단서

가능한 경로를 끝까지 확인하거나, 연결 관계 자체를 조사해야 한다면 DFS가 잘 맞는다.

- “연결된 영역(컴포넌트)의 개수”를 구하라.
- “두 정점 사이에 경로가 존재하는가?”
- “그래프에 사이클이 존재하는가?”
- “모든 경우를 탐색하라.”
- 한 번의 선택을 되돌리고 다른 선택을 해야 하는 백트래킹 문제
- 격자에서 섬, 단지, 그림처럼 붙어 있는 영역의 개수를 세는 문제

대표 예시는 섬의 개수, 연결 요소 개수, 모든 경로 찾기, N-Queen, 순열·조합 생성, 사이클 탐지, 위상 정렬이다.

### BFS를 떠올릴 단서

최소 횟수, 가장 가까운 위치, 동시에 퍼지는 과정이 핵심이면 BFS가 적합할 가능성이 높다.

- “최소 이동 횟수”, “최단 거리”, “가장 빨리 도착”
- 한 번 이동할 때 비용이 모두 동일함
- 상하좌우 한 칸 이동하는 미로에서 출구까지의 최소 칸 수
- 바이러스, 불, 토마토처럼 여러 시작점에서 동시에 퍼짐
- 가장 가까운 사람, 가장 가까운 목표, 몇 단계 만에 도달하는지

대표 예시는 미로 탈출의 최소 이동 거리, 숨바꼭질의 최소 시간, 토마토 익히기, 바이러스/불 확산, 멀티 소스 BFS다.

> “최단 거리”라는 말만으로 BFS를 선택하면 안 된다. 모든 이동 비용이 같을 때만 BFS가 최단 거리를 보장한다. 간선마다 비용이 다르면 보통 다익스트라 알고리즘을 사용한다.

## 격자 문제에서의 BFS 기본 형태

그래프 대신 2차원 배열을 탐색할 때도 원리는 같다. 현재 칸에서 상, 하, 좌, 우를 이웃 정점으로 생각하면 된다.

~~~python
from collections import deque

grid = [
    [1, 1, 0],
    [0, 1, 0],
    [0, 1, 1],
]

rows, cols = len(grid), len(grid[0])
directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

def bfs_grid(start_row, start_col):
    queue = deque([(start_row, start_col)])
    grid[start_row][start_col] = 0  # 방문 처리

    while queue:
        row, col = queue.popleft()

        for dr, dc in directions:
            nr, nc = row + dr, col + dc

            # 범위를 벗어나거나 길이 아닌 칸은 건너뛴다.
            if not (0 <= nr < rows and 0 <= nc < cols):
                continue
            if grid[nr][nc] == 0:
                continue

            grid[nr][nc] = 0
            queue.append((nr, nc))

bfs_grid(0, 0)
~~~

격자 문제에서는 1을 길 또는 아직 방문하지 않은 땅으로, 0을 벽 또는 이미 방문한 칸으로 두는 방식이 흔하다.
