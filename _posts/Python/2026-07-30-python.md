## Python을 공부하기 전에 알아야 할 것

파이썬을 잘 사용하려면 문법만 외우는 것이 아니라 다음 내용을 함께 이해해야 한다.

1. 읽기 좋은 코드를 작성하는 방법
2. 파이썬 코드가 실행되는 과정
3. 객체와 메모리가 관리되는 방식
4. 상황에 맞는 자료구조 선택
5. 로깅과 환경 변수 관리
6. 타입 힌트를 활용한 코드 안정성 확보

결론적으로 좋은 파이썬 코드는 단순히 실행되는 코드가 아니다.

> 다른 사람이 쉽게 읽고, 수정하고, 오류를 추적할 수 있는 코드가 좋은 코드다.

AI가 코드를 빠르게 만들어주는 시대에도 직접 코드를 입력하고 실행해보는 과정은 중요하다. 코드를 직접 작성해야 문법뿐만 아니라 데이터 흐름과 프로그램 구조를 이해할 수 있기 때문이다.

---

## 1. 좋은 코드란 무엇인가

좋은 코드는 복잡한 기술을 많이 사용한 코드가 아니라, 의도를 쉽게 파악할 수 있는 코드다.

### 좋은 코드의 기준

#### 1. 흐름이 단순해야 한다

조건문과 반복문이 지나치게 중첩되면 코드를 이해하기 어려워진다.

```python
# 좋지 않은 예
def process_user(user):
    if user is not None:
        if user.is_active:
            if user.age >= 20:
                return "처리 완료"
    return "처리 불가"
```

조건을 먼저 검사하고 종료하면 흐름을 단순하게 만들 수 있다.

```python
def process_user(user):
    if user is None:
        return "처리 불가"

    if not user.is_active:
        return "처리 불가"

    if user.age < 20:
        return "처리 불가"

    return "처리 완료"
```

이처럼 조건을 먼저 검사하고 함수를 종료하는 방식을 `Early Return`이라고 한다.

---

#### 2. 이름만 보고 역할을 알 수 있어야 한다

파이썬에서는 일반적으로 다음 이름 규칙을 사용한다.

| 대상 | 표기법 | 예시 |
|---|---|---|
| 변수와 함수 | `snake_case` | `total_price` |
| 클래스 | `PascalCase` | `UserService` |
| 상수 | `UPPER_SNAKE_CASE` | `MAX_RETRY_COUNT` |

```python
MAX_RETRY_COUNT = 3


class UserService:
    def get_user_name(self, user_id):
        return "Alice"
```

`data`, `value`, `temp`처럼 의미가 모호한 이름보다 역할이 드러나는 이름을 사용하는 것이 좋다.

```python
# 의미가 모호함
d = 1000
v = 0.1

# 의미가 명확함
product_price = 1000
discount_rate = 0.1
```

---

#### 3. 주석은 무엇보다 왜를 설명해야 한다

코드만 보고 알 수 있는 내용을 주석으로 반복할 필요는 없다.

```python
# count에 1을 더한다
count += 1
```

주석은 코드만으로 알기 어려운 이유나 제약 조건을 설명할 때 효과적이다.

```python
# 외부 API 호출 제한을 피하기 위해 최대 3번까지만 재시도한다.
MAX_RETRY_COUNT = 3
```

> 내가 작성한 코드의 품질은 내가 보장해야 한다. 잘 작성된 코드는 팀원과 소통하기 위한 문서이기도 하다.

## 2. 파이썬 실행 파이프라인

파이썬 소스코드는 바로 CPU가 이해하는 기계어로 변환되는 것이 아니다.

CPython을 기준으로 코드는 다음 과정을 거쳐 실행된다.

```text
소스 코드(.py)
    ↓
토큰화 및 파싱
    ↓
AST 생성
    ↓
바이트코드 컴파일
    ↓
Python Virtual Machine 실행
    ↓
결과 출력 또는 예외 발생
```

이 실행 구조를 이해하면 다음 문제를 해결하는 데 도움이 된다.

- 문법 오류 분석
- 패키지와 파이썬 버전 문제 해결
- 에러 메시지 해석
- 코드 성능 비교
- 린터와 포매터의 동작 이해

---

### 2.1 Parser

#### 정의

파서는 작성한 소스 코드가 파이썬 문법에 맞는지 분석하는 구성 요소다.

```python
print("Hello")
```

파서는 위 코드를 다음과 같은 의미 단위로 분석한다.

- `print`: 함수 이름
- `(`와 `)`: 함수 호출
- `"Hello"`: 문자열 값

문법이 잘못되면 이 단계에서 `SyntaxError`가 발생한다.

```python
if True
    print("Hello")
```

```text
SyntaxError: expected ':'
```

---

### 2.2 AST

#### 정의

AST는 `Abstract Syntax Tree`의 약자로, 소스 코드의 문법 구조를 트리 형태로 표현한 자료구조다.

괄호나 공백 같은 세부 표현보다 변수, 연산, 함수 호출 등 코드의 핵심 의미를 저장한다.

#### 사용 예

다음 코드를 생각해보자.

```python
result = a + b
```

AST에서는 대략 다음 구조로 표현된다.

```text
Assign
├── Name: result
└── BinOp
    ├── Name: a
    ├── Add
    └── Name: b
```

#### 예시 코드

파이썬의 `ast` 모듈로 AST를 확인할 수 있다.

```python
import ast

source_code = "result = a + b"

tree = ast.parse(source_code)

print(ast.dump(tree, indent=4))
```

AST는 다음 도구에서 활용된다.

- 린터
- 포매터
- 정적 분석 도구
- IDE
- 트랜스파일러
- 코드 자동 변환 도구

대표적으로 Black, Ruff, mypy와 같은 개발 도구가 코드의 구조를 분석하는 과정에서 AST와 유사한 구문 정보를 활용한다.

---

### 2.3 Bytecode

#### 정의

바이트코드는 파이썬 가상 머신이 실행할 수 있도록 변환된 중간 명령어다.

CPython은 소스 코드를 CPU 기계어로 직접 변환하는 대신 바이트코드로 컴파일한다.

```text
Python 소스 코드 → Python 바이트코드 → PVM 실행
```

#### `.pyc` 파일

파이썬은 import한 모듈의 바이트코드를 `__pycache__` 디렉터리에 저장할 수 있다.

```text
project/
├── main.py
├── calculator.py
└── __pycache__/
    └── calculator.cpython-314.pyc
```

`.pyc` 파일은 다음 실행에서 소스 코드를 다시 컴파일하는 비용을 줄이는 캐시 역할을 한다.

다만 다음 사항에 주의해야 한다.

- 모든 실행에서 `.pyc` 파일이 생성되는 것은 아니다.
- `.pyc`는 파이썬 구현과 버전에 영향을 받는다.
- 일반적으로 직접 수정하거나 Git에 저장하지 않는다.

```gitignore
__pycache__/
*.pyc
```

---

### 2.4 `dis` 모듈

#### 정의

`dis`는 파이썬 함수가 어떤 바이트코드 명령으로 컴파일되었는지 확인하는 모듈이다.

#### 예시 코드

```python
import dis


def add(a, b):
    return a + b


dis.dis(add)
```

출력에서는 다음과 같은 명령을 확인할 수 있다.

```text
LOAD_FAST
BINARY_OP
RETURN_VALUE
```

각 명령의 의미는 다음과 같다.

- `LOAD_FAST`: 지역 변수를 스택에 올린다.
- `BINARY_OP`: 두 값을 연산한다.
- `RETURN_VALUE`: 결과를 반환한다.

`dis`를 사용하면 두 코드가 내부적으로 어떻게 다르게 실행되는지 비교할 수 있다.

```python
import dis


def use_loop(numbers):
    result = []

    for number in numbers:
        result.append(number * 2)

    return result


def use_comprehension(numbers):
    return [number * 2 for number in numbers]


dis.dis(use_loop)
dis.dis(use_comprehension)
```

리스트 컴프리헨션은 리스트 생성을 위해 최적화된 바이트코드를 사용하므로 일반적인 반복문보다 빠른 경우가 많다.

단, 성능 차이가 크지 않다면 가독성이 높은 코드를 우선하는 것이 좋다.

---

### 2.5 PVM

#### 정의

PVM은 `Python Virtual Machine`의 약자로, 컴파일된 바이트코드를 하나씩 해석하고 실행하는 엔진이다.

CPython의 바이트코드는 대부분 스택 기반으로 처리된다.

다음 연산을 생각해보자.

```python
result = 10 + 20
```

개념적으로는 다음 순서로 실행된다.

```text
10을 스택에 저장
20을 스택에 저장
두 값을 꺼내 더함
결과 30을 스택에 저장
result에 저장
```

#### 실행 파이프라인 요약

```text
.py 파일
→ 파싱
→ AST
→ 바이트코드
→ PVM 실행
→ 결과 또는 예외
```

## 3. 파이썬 객체와 메모리 관리

파이썬에서 변수는 값을 직접 저장하는 상자라기보다, 객체를 가리키는 이름에 가깝다.

```python
number = 10
```

위 코드는 개념적으로 다음과 같이 동작한다.

```text
10이라는 정수 객체 생성
number가 해당 객체를 참조
```

---

### 3.1 모든 값은 객체다

파이썬에서는 정수, 문자열, 함수, 클래스도 객체로 취급된다.

```python
number = 10
text = "Python"


def greet():
    return "Hello"


print(type(number))
print(type(text))
print(type(greet))
```

```text
<class 'int'>
<class 'str'>
<class 'function'>
```

객체는 개념적으로 다음 정보를 가진다.

- 객체의 타입
- 객체가 저장하는 값
- 객체를 참조하는 수
- 객체 동작에 필요한 내부 정보

---

### 3.2 Stack과 Heap

파이썬 메모리를 이해할 때 다음과 같이 단순화할 수 있다.

#### Stack

함수 호출 순서와 실행 프레임을 관리한다.

```python
def first():
    second()


def second():
    print("실행")


first()
```

호출 흐름은 다음과 같다.

```text
first 호출
└── second 호출
    └── print 호출
```

#### Heap

리스트, 딕셔너리, 클래스 인스턴스와 같은 객체가 저장되는 메모리 영역이다.

```python
numbers = [1, 2, 3]
user = {"name": "Alice"}
```

정확히 말하면 지역 변수도 객체 자체를 저장하는 것이 아니라 객체에 대한 참조를 가진다.

---

### 3.3 Reference Counting

#### 정의

CPython은 객체가 몇 곳에서 참조되고 있는지를 계산한다.

참조 수가 0이 되면 해당 객체의 메모리를 해제할 수 있다.

```python
import sys

numbers = [1, 2, 3]

print(sys.getrefcount(numbers))
```

`sys.getrefcount()`는 함수 호출 과정에서 임시 참조가 하나 추가되므로 실제 참조 수보다 1 크게 출력될 수 있다.

```python
numbers = [1, 2, 3]
same_numbers = numbers
```

현재 하나의 리스트 객체를 두 변수가 참조한다.

```text
numbers ────────┐
                ├──> [1, 2, 3]
same_numbers ───┘
```

---

### 3.4 Garbage Collector

#### 정의

참조 횟수만으로 처리하기 어려운 순환 참조 객체를 정리하는 기능이다.

#### 순환 참조 예시

```python
class Node:
    def __init__(self):
        self.next = None


node_a = Node()
node_b = Node()

node_a.next = node_b
node_b.next = node_a
```

`node_a`와 `node_b`가 서로를 참조하므로 외부 참조가 사라져도 참조 횟수가 0이 되지 않을 수 있다.

CPython의 순환 가비지 컬렉터는 이러한 구조를 탐지하여 정리한다.

#### 수동 실행

```python
import gc

collected_count = gc.collect()

print(f"정리된 객체 수: {collected_count}")
```

일반적인 프로그램에서는 파이썬이 자동으로 메모리를 관리하므로 `gc.collect()`를 직접 호출할 필요가 거의 없다.

## 4. 파이썬 주요 자료구조

자료구조를 선택할 때는 데이터의 모양보다 어떤 연산을 자주 수행하는지를 기준으로 판단해야 한다.

| 자료구조 | 주요 특징 | 대표 사용 사례 |
|---|---|---|
| `list` | 순서 유지, 인덱싱 | 데이터 목록 |
| `tuple` | 변경 불가능 | 고정된 좌표 |
| `set` | 중복 제거, 빠른 검색 | 중복 데이터 제거 |
| `dict` | 키와 값 저장 | 사용자 정보 |
| `deque` | 양쪽 삽입과 삭제가 빠름 | 큐, 최근 기록 |
| `defaultdict` | 기본값 자동 생성 | 그룹화 |
| `Counter` | 요소 빈도 계산 | 단어 빈도 |
| `heapq` | 우선순위가 높은 값 처리 | 작업 스케줄링 |
| `bisect` | 정렬 상태를 유지하며 삽입 | 점수 목록 |

---

### 4.1 `deque`

#### 정의

`deque`는 `double-ended queue`의 약자로, 양쪽 끝에서 데이터를 빠르게 추가하거나 제거할 수 있는 자료구조다.

```python
from collections import deque

history = deque()

history.append("Google")
history.append("GitHub")
history.appendleft("Home")

print(history)
```

```text
deque(['Home', 'Google', 'GitHub'])
```

양쪽 끝의 삽입과 삭제는 일반적으로 `O(1)`이다.

```python
history.pop()
history.popleft()
```

#### 사용 예

- 웹 브라우저 방문 기록
- 작업 대기열
- 너비 우선 탐색
- 최근 N개 데이터 저장

```python
from collections import deque

recent_logs = deque(maxlen=3)

recent_logs.append("로그 1")
recent_logs.append("로그 2")
recent_logs.append("로그 3")
recent_logs.append("로그 4")

print(recent_logs)
```

```text
deque(['로그 2', '로그 3', '로그 4'], maxlen=3)
```

CPython의 `deque`는 단순히 노드 하나에 값 하나를 저장하는 연결 리스트가 아니다. 여러 값을 담는 블록들이 양방향으로 연결된 구조를 사용한다.

---

### 4.2 `defaultdict`

#### 정의

존재하지 않는 키를 조회했을 때 지정된 함수를 이용해 기본값을 자동으로 생성하는 딕셔너리다.

일반 딕셔너리에서는 존재하지 않는 키에 접근하면 `KeyError`가 발생한다.

```python
scores = {}

scores["Alice"].append(90)
```

```text
KeyError: 'Alice'
```

`defaultdict`를 사용하면 초기값을 자동으로 만들 수 있다.

```python
from collections import defaultdict

scores = defaultdict(list)

scores["Alice"].append(90)
scores["Alice"].append(85)
scores["Bob"].append(70)

print(scores)
```

```text
defaultdict(<class 'list'>, {
    'Alice': [90, 85],
    'Bob': [70]
})
```

#### 사용 예

- 데이터를 기준별로 그룹화
- 그래프의 인접 리스트
- 항목별 합계 계산

```python
from collections import defaultdict

sales = [
    {"region": "서울", "amount": 1000},
    {"region": "서울", "amount": 1500},
    {"region": "부산", "amount": 800},
]

sales_by_region = defaultdict(int)

for sale in sales:
    sales_by_region[sale["region"]] += sale["amount"]

print(dict(sales_by_region))
```

```text
{'서울': 2500, '부산': 800}
```

---

### 4.3 `Counter`

#### 정의

이터러블에 포함된 요소가 몇 번 등장했는지 계산하는 자료구조다.

```python
from collections import Counter

words = ["python", "java", "python", "rust", "python"]

word_counts = Counter(words)

print(word_counts)
```

```text
Counter({'python': 3, 'java': 1, 'rust': 1})
```

가장 자주 등장한 요소도 쉽게 확인할 수 있다.

```python
print(word_counts.most_common(2))
```

```text
[('python', 3), ('java', 1)]
```

#### 사용 예

- 단어 빈도 분석
- 상품 판매 수량 계산
- 로그 상태 코드 집계
- 투표 결과 집계

```python
from collections import Counter

status_codes = [200, 200, 404, 200, 500, 404]

status_counts = Counter(status_codes)

print(status_counts[200])
```

```text
3
```

---

### 4.4 `OrderedDict`

#### 정의

항목 순서를 세밀하게 제어할 수 있는 딕셔너리다.

Python 3.7부터 일반 `dict`도 삽입 순서를 보장한다. 따라서 단순히 순서를 유지하기 위한 목적으로는 일반 딕셔너리로 충분하다.

`OrderedDict`는 항목 순서를 변경하는 기능이 필요할 때 유용하다.

```python
from collections import OrderedDict

cache = OrderedDict()

cache["A"] = 1
cache["B"] = 2
cache["C"] = 3

cache.move_to_end("A")

print(cache)
```

```text
OrderedDict([('B', 2), ('C', 3), ('A', 1)])
```

#### 사용 예

- LRU 캐시 구현
- 항목 순서 재배치
- 가장 오래된 항목 제거

```python
oldest_key, oldest_value = cache.popitem(last=False)

print(oldest_key, oldest_value)
```

### 4.5 `heapq`

#### 정의

힙은 우선순위가 가장 높은 값을 빠르게 꺼내기 위한 자료구조다.

파이썬의 기본 `heapq` 연산은 작은 값을 먼저 꺼내는 최소 힙 방식이다.

```python
import heapq

numbers = [5, 2, 8, 1, 4]

heapq.heapify(numbers)

print(numbers)
print(heapq.heappop(numbers))
```

```text
1
```

새로운 값을 추가할 수도 있다.

```python
heapq.heappush(numbers, 3)
```

#### 사용 예

- 우선순위 큐
- 작업 스케줄러
- 최단 경로 알고리즘
- 가장 작은 값 N개 찾기

```python
import heapq

tasks = []

heapq.heappush(tasks, (3, "문서 작성"))
heapq.heappush(tasks, (1, "서버 복구"))
heapq.heappush(tasks, (2, "코드 리뷰"))

while tasks:
    priority, task = heapq.heappop(tasks)
    print(priority, task)
```

```text
1 서버 복구
2 코드 리뷰
3 문서 작성
```

힙에서 값을 추가하거나 제거하는 시간 복잡도는 일반적으로 `O(log N)`이다.

---

### 4.6 `bisect`

#### 정의

정렬된 리스트에서 이진 탐색을 이용해 값이 들어갈 위치를 찾거나, 정렬 상태를 유지하며 값을 삽입하는 모듈이다.

```python
from bisect import bisect_left

scores = [60, 70, 80, 90]

index = bisect_left(scores, 75)

print(index)
```

```text
2
```

75는 인덱스 2 위치에 들어가야 정렬 상태가 유지된다.

```python
from bisect import insort

scores = [60, 70, 80, 90]

insort(scores, 75)

print(scores)
```

```text
[60, 70, 75, 80, 90]
```

위치를 찾는 과정은 `O(log N)`이지만, 리스트 중간에 값을 실제로 삽입하는 과정은 요소 이동이 필요하므로 `O(N)`이다.

## 5. 시간 복잡도 `O(log N)`

`O(log N)`은 데이터가 증가하더라도 연산 횟수가 비교적 천천히 증가하는 효율적인 복잡도다.

대표적인 방식은 데이터를 매번 절반씩 줄이는 것이다.

```text
1,024개
→ 512개
→ 256개
→ 128개
→ 64개
→ 32개
→ 16개
→ 8개
→ 4개
→ 2개
→ 1개
```

1,024개의 데이터도 약 10번의 비교로 범위를 좁힐 수 있다.

대표적인 `O(log N)` 연산은 다음과 같다.

- 이진 탐색
- 힙 삽입과 삭제
- 균형 이진 탐색 트리 검색

## 6. `zip()`과 `zip_longest()`

### 6.1 `zip()`

#### 정의

여러 이터러블에서 같은 위치의 값을 하나의 튜플로 묶어주는 함수다.

```python
names = ["Alice", "Bob", "Charlie"]
scores = [90, 80, 95]

result = list(zip(names, scores))

print(result)
```

```text
[('Alice', 90), ('Bob', 80), ('Charlie', 95)]
```

#### 두 리스트를 딕셔너리로 변환하기

```python
keys = ["name", "age", "city"]
values = ["Alice", 25, "Seoul"]

person = dict(zip(keys, values))

print(person)
```

```text
{'name': 'Alice', 'age': 25, 'city': 'Seoul'}
```

#### 묶인 데이터 분리하기

```python
pairs = [
    ("Alice", 25),
    ("Bob", 30),
    ("Charlie", 35),
]

names, ages = zip(*pairs)

print(names)
print(ages)
```

```text
('Alice', 'Bob', 'Charlie')
(25, 30, 35)
```

`zip(*pairs)`는 리스트가 아니라 튜플들을 반환한다. 리스트가 필요하면 변환해야 한다.

```python
names = list(names)
ages = list(ages)
```

#### 점수를 기준으로 이름 정렬하기

```python
students = ["Alice", "Bob", "Charlie"]
scores = [90, 80, 95]

sorted_students = [
    name
    for score, name in sorted(
        zip(scores, students),
        reverse=True,
    )
]

print(sorted_students)
```

```text
['Charlie', 'Alice', 'Bob']
```

---

### 6.2 `zip_longest()`

#### 정의

길이가 서로 다른 이터러블을 끝까지 묶고, 부족한 값을 지정한 기본값으로 채우는 함수다.

일반 `zip()`은 가장 짧은 이터러블을 기준으로 종료된다.

```python
a = [1, 2, 3]
b = ["one", "two"]

print(list(zip(a, b)))
```

```text
[(1, 'one'), (2, 'two')]
```

`3`과 묶일 값이 없으므로 결과에서 제외된다.

`zip_longest()`를 사용하면 부족한 값을 채울 수 있다.

```python
from itertools import zip_longest

a = [1, 2, 3]
b = ["one", "two"]

result = list(
    zip_longest(
        a,
        b,
        fillvalue="없음",
    )
)

print(result)
```

```text
[(1, 'one'), (2, 'two'), (3, '없음')]
```

#### 불완전한 행 정리하기

```python
from itertools import zip_longest

columns = ["이름", "나이", "도시"]

rows = [
    ["Alice", 25],
    ["Bob", 30, "Seoul"],
    ["Charlie"],
]

for row in rows:
    formatted_row = dict(
        zip_longest(
            columns,
            row,
            fillvalue="정보 없음",
        )
    )

    print(formatted_row)
```

```text
{'이름': 'Alice', '나이': 25, '도시': '정보 없음'}
{'이름': 'Bob', '나이': 30, '도시': 'Seoul'}
{'이름': 'Charlie', '나이': '정보 없음', '도시': '정보 없음'}
```

## 7. 문자열 슬라이싱과 포맷팅

### 7.1 문자열 슬라이싱

#### 정의

문자열의 특정 범위를 선택하는 문법이다.

```python
text = "Hello, Python!"

print(text[0:5])
print(text[:5])
print(text[7:])
print(text[::-1])
```

```text
Hello
Hello
Python!
!nohtyP ,olleH
```

슬라이싱 문법은 다음과 같다.

```python
문자열[시작:종료:간격]
```

종료 위치의 문자는 포함되지 않는다.

---

### 7.2 문자열 포맷팅

문자열에 변수 값을 삽입할 때는 현재 파이썬 코드에서 일반적으로 f-string을 사용한다.

```python
name = "Alice"
age = 25

print(f"이름: {name}, 나이: {age}")
```

```text
이름: Alice, 나이: 25
```

소수점 자리도 지정할 수 있다.

```python
temperature = 26.3456

print(f"현재 온도: {temperature:.1f}℃")
```

```text
현재 온도: 26.3℃
```

기존 코드에서는 `%` 연산자나 `format()`도 볼 수 있다.

```python
print("이름: %s, 나이: %d" % (name, age))
print("이름: {}, 나이: {}".format(name, age))
```

새로운 코드를 작성할 때는 특별한 이유가 없다면 f-string을 우선 사용하는 것이 읽기 쉽다.

## 8. 함수와 인자

### 8.1 함수

#### 정의

함수는 특정 작업을 수행하도록 묶은 재사용 가능한 코드 블록이다.

```python
def add(a, b):
    return a + b


result = add(3, 5)

print(result)
```

```text
8
```

`return`은 함수의 결과를 외부로 반환한다.

반환문이 없으면 함수는 기본적으로 `None`을 반환한다.

```python
def print_message():
    print("Hello")


result = print_message()

print(result)
```

```text
Hello
None
```

---

### 8.2 기본값 인자

함수를 호출할 때 인자를 생략할 수 있도록 기본값을 지정할 수 있다.

```python
def greet(name, message="안녕하세요"):
    return f"{message}, {name}님!"


print(greet("철수"))
print(greet("영희", "반갑습니다"))
```

```text
안녕하세요, 철수님!
반갑습니다, 영희님!
```

기본값이 있는 매개변수는 기본값이 없는 매개변수보다 뒤에 배치해야 한다.

---

### 8.3 `*args`

#### 정의

여러 개의 위치 인자를 튜플로 전달받는 문법이다.

```python
def greet_many(message, *names):
    for name in names:
        print(f"{message}, {name}님!")


greet_many(
    "안녕하세요",
    "Alice",
    "Bob",
    "Charlie",
)
```

`names`에는 다음 튜플이 저장된다.

```python
("Alice", "Bob", "Charlie")
```

---

### 8.4 `**kwargs`

#### 정의

여러 개의 키워드 인자를 딕셔너리로 전달받는 문법이다.

```python
def print_user(**user):
    for key, value in user.items():
        print(f"{key}: {value}")


print_user(
    name="Alice",
    age=25,
    city="Seoul",
)
```

`user`에는 다음 딕셔너리가 저장된다.

```python
{
    "name": "Alice",
    "age": 25,
    "city": "Seoul",
}
```

---

### 8.5 Lambda

#### 정의

간단한 연산을 한 줄로 작성하는 익명 함수다.

```python
multiply = lambda a, b: a * b

print(multiply(3, 4))
```

```text
12
```

주로 정렬 기준이나 짧은 변환 함수를 전달할 때 사용한다.

```python
users = [
    {"name": "Alice", "age": 25},
    {"name": "Bob", "age": 20},
]

sorted_users = sorted(
    users,
    key=lambda user: user["age"],
)

print(sorted_users)
```

복잡한 로직은 `lambda`보다 일반 함수로 작성하는 것이 좋다.

---

### 8.6 Closure

#### 정의

내부 함수가 외부 함수의 변수를 기억하는 구조다.

```python
def create_multiplier(number):
    def multiply(value):
        return value * number

    return multiply


double = create_multiplier(2)
triple = create_multiplier(3)

print(double(10))
print(triple(10))
```

```text
20
30
```

`double` 함수는 `create_multiplier()` 실행이 끝난 뒤에도 `number=2`를 기억한다.

---

### 8.7 `functools.partial`

#### 정의

기존 함수의 일부 인자를 미리 고정하여 새로운 함수를 만드는 기능이다.

```python
from functools import partial


def power(base, exponent):
    return base**exponent


square = partial(power, exponent=2)
cube = partial(power, exponent=3)

print(square(4))
print(cube(4))
```

```text
16
64
```

## 9. `logging`: `print()`보다 체계적인 기록

운영 프로그램에서는 `print()`보다 `logging`을 사용하는 것이 좋다.

`logging`은 다음 기능을 제공한다.

- 로그 중요도 구분
- 파일 저장
- 시간과 코드 위치 기록
- 날짜별 로그 파일 분리
- 에러 로그 별도 저장

---

### 9.1 로그 레벨

| 레벨 | 의미 |
|---|---|
| `DEBUG` | 디버깅을 위한 상세 정보 |
| `INFO` | 정상적인 실행 흐름 |
| `WARNING` | 문제가 될 가능성이 있는 상황 |
| `ERROR` | 오류가 발생했지만 실행은 계속 가능 |
| `CRITICAL` | 서비스 중단 가능성이 있는 심각한 오류 |

#### 기본 사용법

```python
import logging

logging.basicConfig(level=logging.INFO)

logging.debug("디버깅 정보")
logging.info("서비스가 시작되었습니다.")
logging.warning("설정 값이 누락되었습니다.")
logging.error("파일을 찾을 수 없습니다.")
logging.critical("서비스를 계속 실행할 수 없습니다.")
```

`INFO` 레벨을 설정하면 `DEBUG` 로그는 출력되지 않는다.

---

### 9.2 실무 로깅 예시

다음 코드는 로그를 콘솔과 파일에 서로 다른 기준으로 저장한다.

```python
import logging
import os
from logging.handlers import TimedRotatingFileHandler

LOG_DIRECTORY = "logs"

os.makedirs(
    LOG_DIRECTORY,
    exist_ok=True,
)

logger = logging.getLogger("MyApp")
logger.setLevel(logging.DEBUG)

# 핸들러가 중복 등록되는 것을 방지한다.
if not logger.handlers:
    console_handler = logging.StreamHandler()
    console_handler.setLevel(logging.INFO)

    console_formatter = logging.Formatter(
        "[%(levelname)s] %(message)s"
    )
    console_handler.setFormatter(console_formatter)

    file_handler = TimedRotatingFileHandler(
        filename=f"{LOG_DIRECTORY}/app.log",
        when="midnight",
        interval=1,
        backupCount=7,
        encoding="utf-8",
    )
    file_handler.setLevel(logging.DEBUG)

    file_formatter = logging.Formatter(
        "%(asctime)s | %(levelname)s | "
        "%(filename)s:%(lineno)d | %(message)s"
    )
    file_handler.setFormatter(file_formatter)

    error_handler = logging.FileHandler(
        f"{LOG_DIRECTORY}/error.log",
        encoding="utf-8",
    )
    error_handler.setLevel(logging.ERROR)
    error_handler.setFormatter(file_formatter)

    logger.addHandler(console_handler)
    logger.addHandler(file_handler)
    logger.addHandler(error_handler)

logger.debug("디버그 정보")
logger.info("정상 흐름")
logger.warning("경고 메시지")
logger.error("에러 발생")
logger.critical("치명적 오류")
```

이 설정의 결과는 다음과 같다.

- 콘솔: `INFO` 이상 출력
- `app.log`: `DEBUG` 이상 저장
- `error.log`: `ERROR` 이상 저장
- `app.log`: 자정마다 새로운 파일로 회전
- 오래된 로그: 최근 7개까지 보관

## 10. `.env`와 환경 변수

API 키와 데이터베이스 비밀번호는 소스 코드에 직접 작성하면 안 된다.

```python
# 위험한 예
API_KEY = "sk-example-secret-key"
DB_PASSWORD = "1234"
```

GitHub에 코드가 올라가면 민감 정보가 함께 노출될 수 있다.

---

### 10.1 환경 변수

#### 정의

프로그램 외부에서 설정값을 전달하기 위한 값이다.

대표적인 사용 대상은 다음과 같다.

- API 키
- 데이터베이스 주소
- 데이터베이스 비밀번호
- 실행 환경
- 디버그 설정

---

### 10.2 `.env` 파일

프로젝트 루트에 다음과 같은 `.env` 파일을 만들 수 있다.

```dotenv
API_KEY=sk-example
DB_URL=postgresql://user:password@localhost/app
ENV=development
DEBUG=true
```

파이썬에서는 `python-dotenv`를 이용해 읽을 수 있다.

```bash
pip install python-dotenv
```

```python
import os

from dotenv import load_dotenv

load_dotenv()

api_key = os.getenv("API_KEY")
db_url = os.getenv("DB_URL")
environment = os.getenv("ENV", "development")

print(f"현재 환경: {environment}")
```

`os.getenv()`의 두 번째 인자는 환경 변수가 없을 때 사용할 기본값이다.

---

### 10.3 Git 연동 시 주의사항

`.env`는 반드시 `.gitignore`에 등록해야 한다.

```gitignore
.env
.env.local
.env.development
.env.production
```

팀원에게는 실제 비밀번호가 없는 `.env.example` 파일을 공유한다.

```dotenv
API_KEY=
DB_URL=
ENV=development
DEBUG=false
```

팀원은 해당 파일을 복사하여 자신의 `.env` 파일을 만든다.

```bash
cp .env.example .env
```

운영 환경에서는 `.env` 파일만 사용하는 것보다 다음 비밀 관리 기능을 사용하는 것이 안전하다.

- GitHub Actions Secrets
- Docker Secrets
- AWS Secrets Manager
- Google Secret Manager
- HashiCorp Vault

## 11. 타입 힌트

타입 힌트는 변수, 매개변수, 반환값이 어떤 타입을 가져야 하는지 표시하는 문법이다.

```python
def add(a: int, b: int) -> int:
    return a + b
```

타입 힌트는 일반적으로 파이썬 런타임에서 타입을 강제로 제한하지 않는다.

```python
def add(a: int, b: int) -> int:
    return a + b


print(add("A", "B"))
```

```text
AB
```

실행은 가능하지만 mypy나 Pylance 같은 정적 타입 검사 도구는 잘못된 사용으로 표시할 수 있다.

타입 힌트의 목적은 다음과 같다.

- IDE 자동완성 향상
- 함수 사용 방법 문서화
- 잘못된 인자 전달 방지
- 팀 간 데이터 형식 공유
- 정적 타입 검사

---

### 11.1 기본 타입 힌트

```python
from typing import Any


def clean_name(name: str) -> str:
    return name.strip().lower()


def compute_average(values: list[float]) -> float:
    return sum(values) / len(values)


def lookup(
    data: dict[str, Any],
    key: str,
    default: float = 0.0,
) -> float:
    return float(data.get(key, default))
```

주요 타입은 다음과 같다.

```python
name: str
age: int
temperature: float
is_active: bool
numbers: list[int]
user: dict[str, str]
coordinate: tuple[float, float]
```

---

### 11.2 Union과 Optional

여러 타입을 허용하려면 `|` 문법을 사용할 수 있다.

```python
def parse_value(
    value: str | int | None,
) -> str:
    if value is None:
        return ""

    return str(value)
```

```python
str | int
```

위 타입은 문자열 또는 정수를 의미한다.

```python
int | None
```

위 타입은 정수 또는 `None`을 의미한다.

기존 코드에서는 다음 문법도 볼 수 있다.

```python
from typing import Optional, Union

value: Union[str, int]
age: Optional[int]
```

---

### 11.3 Literal

#### 정의

정해진 값 중 하나만 허용한다는 의미를 타입으로 표현한다.

```python
from typing import Literal

SortMode = Literal[
    "temperature-desc",
    "temperature-asc",
    "name",
]


def sort_weather(
    mode: SortMode,
) -> None:
    print(f"정렬 기준: {mode}")
```

```python
sort_weather("name")
```

허용되지 않은 값을 전달하면 정적 타입 검사 도구가 오류로 표시한다.

```python
sort_weather("random")
```

---

### 11.4 Generic

#### 정의

자료형만 다르고 동작은 같은 코드를 재사용하기 위한 타입 문법이다.

```python
from typing import Generic, TypeVar

T = TypeVar("T")


class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()


number_stack = Stack[int]()
number_stack.push(10)
number_stack.push(20)

print(number_stack.pop())
```

문자열 스택도 같은 클래스로 만들 수 있다.

```python
text_stack = Stack[str]()
text_stack.push("Python")

print(text_stack.pop())
```

`Stack[int]`는 정수를 저장하는 스택이라는 의미다.

---

### 11.5 Protocol

#### 정의

클래스가 특정 클래스를 상속했는지가 아니라, 필요한 메서드를 가지고 있는지를 기준으로 타입을 검사하는 방식이다.

이는 파이썬의 Duck Typing을 정적 타입 검사에 적용한 것이다.

> 오리처럼 걷고 오리처럼 소리를 내면 오리로 취급한다.

```python
from typing import Protocol


class SupportsWrite(Protocol):
    def write(self, text: str) -> None:
        ...


def write_hello(
    writer: SupportsWrite,
) -> None:
    writer.write("Hello\n")


class ConsoleWriter:
    def write(self, text: str) -> None:
        print(f"출력: {text}")


write_hello(ConsoleWriter())
```

`ConsoleWriter`는 `SupportsWrite`를 직접 상속하지 않았지만, 필요한 `write()` 메서드를 가지고 있으므로 사용할 수 있다.

---

### 11.6 Callable

#### 정의

함수를 인자로 받거나 반환할 때 함수의 매개변수와 반환 타입을 표현하는 타입이다.

```python
from collections.abc import Callable


def compute(
    x: int,
    y: int,
    operation: Callable[[int, int], int],
) -> int:
    return operation(x, y)


result = compute(
    3,
    4,
    lambda a, b: a + b,
)

print(result)
```

```text
7
```

```python
Callable[[int, int], int]
```

위 타입은 정수 두 개를 받고 정수 하나를 반환하는 함수를 의미한다.

## 12. mypy와 Pylance

타입 힌트만 작성한다고 오류가 자동으로 차단되는 것은 아니다.

정적 타입 검사 도구를 함께 사용해야 한다.

---

### 12.1 mypy

#### 정의

프로그램을 실행하기 전에 타입 힌트를 분석해 잘못된 타입 사용을 찾아주는 도구다.

```bash
pip install mypy
```

다음 코드에는 타입 오류가 있다.

```python
def compute_average(
    values: list[float],
) -> float:
    return sum(values) / len(values)


result = compute_average(
    ["a", "b", "c"]
)
```

mypy를 실행한다.

```bash
mypy analysis.py
```

다음과 유사한 오류를 확인할 수 있다.

```text
Argument 1 to "compute_average"
has incompatible type "list[str]";
expected "list[float]"
```

CI/CD에서 mypy를 실행하면 타입 검사를 통과하지 못한 코드를 자동으로 차단할 수도 있다.

---

### 12.2 Pylance

Pylance는 VS Code에서 파이썬 타입 정보를 분석하여 다음 기능을 제공한다.

- 자동완성
- 타입 오류 표시
- 함수 매개변수 안내
- 정의 위치 이동
- 사용되지 않는 변수 탐지

mypy가 명령줄과 CI에서 검사하는 도구라면, Pylance는 코드를 작성하는 동안 IDE에서 즉시 피드백을 제공하는 도구에 가깝다.

## 13. Pydantic을 이용한 데이터 검증

타입 힌트와 Pydantic의 역할은 다르다.

- 타입 힌트: 코드의 예상 타입을 표현한다.
- mypy: 실행 전에 타입 사용을 검사한다.
- Pydantic: 실제 실행 중 들어온 데이터를 검증한다.

Pydantic은 API 응답, 사용자 입력, CSV 데이터처럼 외부에서 들어오는 데이터를 검증할 때 유용하다.

---

### 13.1 기본 모델

```bash
pip install pydantic
```

```python
from pydantic import BaseModel


class Sale(BaseModel):
    region: str
    category: str
    amount: int
    month: str


sale = Sale(
    region="서울",
    category="전자",
    amount=1500,
    month="2026-07",
)

print(sale)
```

데이터 타입이 잘못되면 `ValidationError`가 발생한다.

```python
from pydantic import ValidationError

try:
    sale = Sale(
        region="서울",
        category="전자",
        amount="금액 없음",
        month="2026-07",
    )
except ValidationError as error:
    print(error)
```

Pydantic 검증은 프로그램 실행 중 발생한다. 따라서 Pydantic이 오류를 런타임 전에 찾아준다고 표현하면 정확하지 않다.

---

### 13.2 조건 검증

필드에 조건을 설정할 수도 있다.

```python
from pydantic import BaseModel, Field


class Product(BaseModel):
    name: str
    price: int = Field(ge=0)
    stock: int = Field(ge=0)


product = Product(
    name="키보드",
    price=50000,
    stock=10,
)
```

`ge=0`은 값이 0 이상이어야 한다는 의미다.

```python
Product(
    name="키보드",
    price=-1000,
    stock=10,
)
```

음수 가격이 입력되면 검증 오류가 발생한다.

---

### 13.3 CSV 데이터 검증

```python
from pydantic import BaseModel, ValidationError


class Sale(BaseModel):
    region: str
    amount: int


rows = [
    {"region": "서울", "amount": 1500},
    {"region": "부산", "amount": "잘못된 값"},
    {"region": "대전", "amount": 900},
]

valid_sales: list[Sale] = []
errors: list[dict] = []

for index, row in enumerate(rows):
    try:
        sale = Sale.model_validate(row)
        valid_sales.append(sale)

    except ValidationError as error:
        errors.append(
            {
                "row_index": index,
                "data": row,
                "error": error.errors(),
            }
        )

print(valid_sales)
print(errors)
```

분석 파이프라인에서는 다음 전략을 선택할 수 있다.

- 오류가 하나라도 있으면 전체 처리를 중단
- 잘못된 행만 제외
- 오류 행을 별도 파일로 저장
- 오류 개수와 원인을 집계

---

### 13.4 JSON Schema 생성

Pydantic 모델에서 JSON Schema를 생성할 수 있다.

```python
schema = Sale.model_json_schema()

print(schema)
```

이 스키마는 FastAPI의 요청과 응답 모델, OpenAPI 문서와 연결할 수 있다.

## 14. 최종 요약

### 좋은 코드

- 흐름을 단순하게 유지한다.
- 변수와 함수 이름으로 역할을 표현한다.
- 주석은 코드가 아니라 이유를 설명한다.
- 작성한 코드의 품질은 작성자가 책임진다.

### 파이썬 실행 구조

```text
소스 코드
→ 파싱
→ AST
→ 바이트코드
→ PVM
→ 실행 결과
```

- AST는 코드의 문법 구조를 트리로 표현한다.
- 바이트코드는 PVM이 실행하는 중간 명령어다.
- `.pyc`는 바이트코드를 재사용하기 위한 캐시 파일이다.
- `dis`로 함수의 바이트코드를 확인할 수 있다.

### 메모리 관리

- 파이썬의 값은 객체로 관리된다.
- 변수는 객체를 참조한다.
- CPython은 참조 횟수를 이용해 객체를 관리한다.
- 순환 참조는 가비지 컬렉터가 탐지한다.

### 자료구조

- `deque`: 양방향 삽입과 삭제
- `defaultdict`: 기본값 자동 생성
- `Counter`: 빈도 계산
- `OrderedDict`: 항목 순서 조정
- `heapq`: 우선순위 큐
- `bisect`: 정렬된 리스트 검색과 삽입

### 함수

- `*args`: 여러 위치 인자를 튜플로 전달
- `**kwargs`: 여러 키워드 인자를 딕셔너리로 전달
- `lambda`: 짧은 익명 함수
- 클로저: 외부 함수의 값을 기억하는 함수
- `partial`: 일부 인자를 고정한 함수 생성

### 실무 설정

- 운영 코드에서는 `print()`보다 `logging`을 사용한다.
- API 키와 비밀번호는 `.env` 또는 비밀 관리 서비스에 저장한다.
- `.env` 파일은 Git에 올리지 않는다.
- `.env.example`을 이용해 필요한 환경 변수 목록을 공유한다.

### 타입과 데이터 검증

- 타입 힌트는 코드의 예상 타입을 표현한다.
- mypy와 Pylance는 정적으로 타입을 검사한다.
- Pydantic은 실행 중 실제 데이터를 검증한다.
- Generic은 타입이 다른 공통 자료구조를 만든다.
- Protocol은 상속이 아닌 객체의 동작을 기준으로 검사한다.
- Callable은 함수의 입력과 반환 타입을 표현한다.

## 마무리

파이썬을 공부할 때 모든 문법을 한 번에 암기할 필요는 없다.

중요한 것은 다음 세 가지다.

1. 코드가 어떤 순서로 실행되는지 이해한다.
2. 문제에 맞는 자료구조를 선택한다.
3. 다른 사람이 읽을 수 있는 형태로 작성한다.

문법은 필요할 때 다시 찾아볼 수 있다. 하지만 코드의 흐름을 파악하고 데이터를 구조화하는 능력은 직접 코드를 작성하고 오류를 해결하는 과정에서 만들어진다.

AI가 생성한 코드를 그대로 사용하는 것보다, 한 줄씩 입력하고 실행 결과를 확인하면서 구조를 이해하는 습관을 들이는 것이 중요하다.
