# 컴포넌트 설계 

'''
ref/reactive → props → emit → slot → composable → Pinia
'''

상태를 어디에 둘 것인가? 누가 상태를 변경할 것인가? 무엇을 재사용할 것인가. 

Vue 공식 문서도 컴포넌트를 독립적으로 재사용 가능한 UI 조각으로 설명해야 한다. 

# 1. 전체 구조부터 이해하기 

기능	해결하는 질문
ref, reactive	이 컴포넌트가 기억해야 할 상태는 무엇인가?
props	부모가 자식에게 무엇을 알려주는가?
emit	자식이 부모에게 무엇을 요청하는가?
slot	컴포넌트 내부의 어떤 UI를 사용자가 교체할 수 있는가?
composable	여러 컴포넌트에서 반복되는 로직은 무엇인가?
Pinia	여러 페이지와 컴포넌트가 공유해야 하는 상태는 무엇인가?

가장 중요한 설계 원칙은 

인용 : 상태는 필요한 범위 중 가장 작은 범위에 둔다 .

편하자고 전역 변수를 설정하는 것이 만능은 아니다. 

-> 모든 것에는 Trade-off가 존재한다. 

한 컴포넌트 
-> ref / reactive 

부모와 자식이 사용 
-> props / emit 

여러 컴포넌트에서 같은 로직 사용 
-> composable 

서로 멀리 떨어진 컴포넌트나 페이지가 같은 상태 사용 
-> Pinia 

# 2. ref / reactive: 컴포넌트 자신의 상태

왜 사용하는가?

웹 화면은 사용자의 행동에 따라 계속 변한다. 

예를 들어서

입력창에 작성한 문자열
버튼 클릭 횟수
모달 열림 여부
선택된 게시글
로딩 상태
에러 메시지

이런 값이 변경되면 화면도 자동으로 변경되어야 한다.

<script setup>
import { ref } from 'vue'

const count = ref(0)

const increase = () => {
  count.value++
}
</script>

<template>
  <button @click="increase">
    {{ count }}
  </button>
</template>

count가 변경되면 Vue가 이를 감지하여 필요한 화면을 다시 렌더링합니다. ref()는 원시값뿐 아니라 객체와 배열도 반응형으로 만들 수 있습니다.

# 3. ref와 reactive의 선택 기준 

ref

하나의 독립적인 값을 관리할 때 기본적으로 사용

const name = ref('')
const count = ref(0)
const isOpen = ref(false)
const selectedProduct = ref(null)

reactive 

관련된 여러 값을 하나의 객체로 묶고 싶을 때 사용할 수 있다. 

const form = reactive({
  name: '',
  email: '',
  age: 0
})

## 설계 기준 

해당 컴포넌트에서만 사용하는 상태
컴포넌트가 사라지면 함께 사라져도 되는 상태
다른 페이지가 알 필요 없는 상태

예시 

const isDropdownOpen = ref(false)
const inputValue = ref('')
const isHovered = ref(false)

이런 값까지 Pinia로 넣어버린다면, 오히려 상태를 추적하기 어려워진다. 

# 3. Props:부모가 자식에게 데이터를 저달
 
## 왜 사용하는가? 

자식 컴포넌트가 외부 데이터를 직접 찾아오게 만들면 재사용하기가 어려워진다.
예를 들어 ProductCard가 내부에서 특정 상품을 직접 가져온다고 하면 

<ProductCard />

이 컴포넌트는 특정 상품에 종속 

반면 상품 정보를 props로 받으면:

<ProductCard :product="productA" />
<ProductCard :product="productB" />
<ProductCard :product="productC" />

하나의 컴포넌트로 여러 상품을 표현할 수 있다. 

<!-- ProductCard.vue -->
<script setup>
defineProps({
  product: {
    type: Object,
    required: true
  }
})
</script>

<template>
  <article>
    <h2>{{ product.name }}</h2>
    <p>{{ product.price }}원</p>
  </article>
</template>

## Props의 역할

Props는 컴포넌트의 입력 인터페이스 

함수와 비교하면 이해하기 쉽다. 

function calculatePrice(price) {
  return price * 0.9
}

여기서 price가 함수의 입력이라면 

<ProductCard :product="product" />

여기서 product가 컴포넌트의 입력 

Props는 부모에서 자식으로 내려가는 단방향 데이터 흐름을 따르며, 자식은 받은 props를 직접 변경하지 않는 것이 원칙. Vue 역시 props를 읽기 전용으로 다루고, 부모 상태가 변경되면 새로운 값이 자식에게 내려오도록 설계되어 있다. 

## 설계 기준

다음과 같은 값은 props로 전달.

- 부모가 소유하고 있는 데이터
- 자식이 화면에 표시해야 하는 데이터
- 자식의 동작이나 모양을 설정하는 값
