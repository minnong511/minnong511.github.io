# DOM(Document Object Model)이란?

## 정의

> **HTML 문서를 JavaScript가 조작할 수 있도록 브라우저가 메모리에 만든 객체 구조(Tree 구조)**

입니다.

쉽게 말하면:

**HTML 파일 → 브라우저가 읽음 → DOM이라는 객체 형태로 변환 → JavaScript가 조작**

하는 과정입니다.

---

예를 들어 HTML이 있습니다.

```html
<html>
  <body>
    <h1>Hello</h1>
    <p>Vue 공부</p>
  </body>
</html>
```

브라우저는 이것을:

```
Document
│
└── html
    │
    └── body
        │
        ├── h1
        │    └── "Hello"
        │
        └── p
             └── "Vue 공부"
```

이런 **트리 구조 객체**로 만듭니다.

이게 DOM입니다.

---

# 왜 DOM이 필요한가?

HTML은 원래 정적인 문서입니다.

예:

```html
<h1>Hello</h1>
```

브라우저가 화면에 보여주는 것까지는 가능합니다.

하지만:

"버튼 클릭하면 글자가 바뀌게 해줘"

같은 동적인 동작은 HTML만으로 어렵습니다.

그래서 JavaScript가 DOM을 조작합니다.

---

# JavaScript로 DOM 조작 예시

HTML:

```html
<h1 id="title">
Hello
</h1>
```

JavaScript:

```javascript
const title = document.querySelector("#title")

title.innerText = "Hello Vue"
```

결과:

화면:

변경 전:

```
Hello
```

변경 후:

```
Hello Vue
```

---

흐름:

```
HTML
 ↓
브라우저
 ↓
DOM 생성
 ↓
JavaScript가 DOM 수정
 ↓
화면 변경
```

---

# DOM은 그냥 HTML인가?

아닙니다.

중요한 차이:

HTML:

```html
<h1>Hello</h1>
```

문자열(텍스트 문서)

---

DOM:

```javascript
{
 tag:"h1",
 children:[
   "Hello"
 ]
}
```

객체 구조

---

즉:

| |HTML|DOM|
|-|-|-|
|형태|문서|객체|
|목적|내용 표현|프로그램 조작|
|관리 주체|파일|브라우저 메모리|

---

# 그런데 DOM 조작이 왜 문제가 됨?

여기서 Vue가 등장합니다.

예:

게시판에 글 10,000개가 있다고 생각해봅시다.

사용자가 좋아요 버튼 클릭:

```
좋아요 10
↓
좋아요 11
```

변경해야 합니다.

순수 JavaScript:

```javascript
element.innerText = 11
```

직접 DOM 수정

---

문제:

개발자가 직접:

- 어떤 DOM을 바꿀지
- 언제 바꿀지
- 어떤 순서로 바꿀지

관리해야 합니다.

프로젝트가 커지면:

```
데이터
 ↓
DOM
 ↓
다른 DOM
 ↓
이벤트
 ↓
다른 데이터
```

관리가 복잡해집니다.

---

# Vue의 방식

Vue는:

"DOM을 직접 만지지 말고 데이터만 변경해"

라는 철학입니다.

예:

```javascript
const count = ref(0)

count.value++
```

개발자는:

```
데이터 변경
```

만 합니다.

Vue가:

```
데이터 변경
 ↓
반응성 시스템 감지
 ↓
Virtual DOM 생성
 ↓
기존 DOM과 비교
 ↓
필요한 부분만 수정
```

합니다.

---

# Real DOM vs Virtual DOM

## Real DOM

실제 브라우저 화면을 구성하는 DOM

```
Browser Memory

<html>
 └── body
      └── div
           └── button
```

---

## Virtual DOM

Vue가 메모리에 따로 가지고 있는 가상 DOM

```
JavaScript Memory

{
 type:"button",
 text:"Click"
}
```

---

변경 발생:

기존:

```
Virtual DOM A

<button>
Count:0
</button>
```

변경:

```
Virtual DOM B

<button>
Count:1
</button>
```

Vue가 비교:

```
A와 B 비교

Count 부분만 변경 필요
```

실제 DOM:

```
Count:1
```

---

# Vue 관점에서 DOM 이해 흐름

가장 중요한 흐름:

```
사용자 행동
      ↓
데이터 변경
      ↓
ref/reactive
      ↓
Vue 반응성 시스템
      ↓
Virtual DOM 비교
      ↓
Real DOM 업데이트
      ↓
화면 변경
```

---

지금까지 배운 개념을 연결하면:

```
ref/reactive
      ↓
상태(state)
      ↓
변경 감지
      ↓
Virtual DOM
      ↓
DOM 업데이트
      ↓
화면
```

입니다.

다음으로 **"브라우저 렌더링 과정(Critical Rendering Path) → DOM 생성 → Vue 렌더링 과정"**을 공부해야함
