# Vue 프로젝트 

Vue 3 + Vite 프로젝트는 보통 아래 구조로 되어 있습니다. 핵심은 **`src`가 실제 개발 공간이고, 그 안에서 페이지·컴포넌트·라우터·상태를 분리한다**는 것입니다. 




# 기본 프로젝트 구조

```text
skala-vue/
├── .vscode/
├── node_modules/
├── public/
├── src/
│   ├── assets/
│   ├── components/
│   ├── views/
│   ├── router/
│   ├── stores/
│   ├── App.vue
│   ├── main.js
│   └── style.css
├── .env
├── .gitignore
├── index.html
├── package.json
├── package-lock.json
├── vite.config.js
└── README.md
```

# 1. `index.html`

브라우저가 가장 먼저 읽는 **실제 HTML 파일**입니다.

```html
<div id="app"></div>

<script type="module" src="/src/main.js"></script>
```

Vue가 만드는 모든 화면은 최종적으로 다음 영역에 들어갑니다.

```html
<div id="app"></div>
```

실행 흐름은 다음과 같습니다.

```text
index.html
→ main.js 실행
→ Vue 앱 생성
→ App.vue를 #app에 연결
```

---

# 2. `src/main.js`

Vue 애플리케이션을 초기화하는 **JavaScript 진입점**입니다.

```javascript
import './style.css'

import { createApp } from 'vue'
import { createPinia } from 'pinia'

import App from './App.vue'
import router from './router'

const app = createApp(App)

app.use(createPinia())
app.use(router)

app.mount('#app')
```

주요 역할은 다음과 같습니다.

- Vue 앱 생성
- 최상위 컴포넌트인 `App.vue` 등록
- Vue Router 등록
- Pinia 등록
- 전역 CSS 등록
- `index.html`의 `#app`에 Vue 앱 부착

즉, `main.js`는 Vue 애플리케이션의 **조립 및 시동 담당 파일**입니다.

---

# 3. `src/App.vue`

애플리케이션의 **최상위 Root Component**입니다.

```vue
<script setup>
import { RouterLink, RouterView } from 'vue-router'
</script>

<template>
  <header>
    <RouterLink to="/">홈</RouterLink>
    <RouterLink to="/about">소개</RouterLink>
  </header>

  <main>
    <RouterView />
  </main>
</template>
```

보통 다음 내용을 배치합니다.

- 공통 Header
- Navigation
- Footer
- `RouterView`
- 앱 전체 레이아웃

`App.vue`가 모든 화면 내용을 직접 가지기보다, 전체 골격만 담당하는 것이 좋습니다.

---

# 4. `src/components`

여러 페이지에서 재사용할 수 있는 **작은 UI 부품**을 저장합니다.

```text
components/
├── BaseButton.vue
├── SearchBar.vue
├── WeatherCard.vue
├── AppHeader.vue
└── AppModal.vue
```

예를 들어 `WeatherCard.vue`는 날씨 카드 하나만 담당합니다.

```vue
<script setup>
defineProps({
  cityName: String,
  temperature: Number,
})
</script>

<template>
  <article class="weather-card">
    <h2>{{ cityName }}</h2>
    <p>{{ temperature }}℃</p>
  </article>
</template>
```

컴포넌트는 다음 기준으로 분리합니다.

- 독립된 역할이 있는가?
- 다른 화면에서도 재사용할 수 있는가?
- 하나의 파일이 너무 커졌는가?
- 반복되는 UI인가?

---

# 5. `src/views`

URL 하나에 대응하는 **페이지 단위 컴포넌트**를 저장합니다.

```text
views/
├── HomeView.vue
├── AboutView.vue
├── WeatherDetailView.vue
├── LoginView.vue
└── NotFoundView.vue
```

예를 들어 다음 URL이 있다면:

```text
/                 → HomeView.vue
/about            → AboutView.vue
/weather/city_01  → WeatherDetailView.vue
```

`views`는 페이지 전체를 담당하고, 내부에서 여러 `components`를 조립합니다.

```vue
<script setup>
import SearchBar from '@/components/SearchBar.vue'
import WeatherCard from '@/components/WeatherCard.vue'
</script>

<template>
  <main>
    <SearchBar />

    <section>
      <WeatherCard />
      <WeatherCard />
    </section>
  </main>
</template>
```

## `views`와 `components` 차이

| 구분 | `views` | `components` |
|---|---|---|
| 역할 | 페이지 단위 화면 | 재사용 가능한 UI 부품 |
| Router 연결 | 직접 연결 | 보통 직접 연결하지 않음 |
| 재사용성 | 비교적 낮음 | 높음 |
| 예시 | `HomeView.vue` | `WeatherCard.vue` |

# 6. `src/router`

URL과 페이지 컴포넌트를 연결하는 **Vue Router 설정**을 저장합니다.

```text
router/
└── index.js
```

예:

```javascript
import { createRouter, createWebHistory } from 'vue-router'

import HomeView from '@/views/HomeView.vue'

const router = createRouter({
  history: createWebHistory(),

  routes: [
    {
      path: '/',
      name: 'home',
      component: HomeView,
    },
    {
      path: '/about',
      name: 'about',
      component: () => import('@/views/AboutView.vue'),
    },
    {
      path: '/weather/:cityId',
      name: 'weather-detail',
      component: () => import('@/views/WeatherDetailView.vue'),
    },
    {
      path: '/:pathMatch(.*)*',
      name: 'not-found',
      component: () => import('@/views/NotFoundView.vue'),
    },
  ],
})

export default router
```

`component: () => import(...)` 방식은 해당 페이지가 필요할 때 불러오는 **Lazy Loading**입니다.

---

# 7. `src/stores`

Pinia를 사용하는 경우, 여러 컴포넌트가 공유할 **전역 상태**를 저장합니다.

```text
stores/
├── authStore.js
├── configStore.js
└── weatherStore.js
```

예:

```javascript
import { computed, ref } from 'vue'
import { defineStore } from 'pinia'

export const useConfigStore = defineStore('config', () => {
  const unit = ref('celsius')

  const unitSymbol = computed(() => {
    return unit.value === 'celsius' ? '℃' : '℉'
  })

  const toggleUnit = () => {
    unit.value =
      unit.value === 'celsius'
        ? 'fahrenheit'
        : 'celsius'
  }

  return {
    unit,
    unitSymbol,
    toggleUnit,
  }
})
```

Store는 보통 다음 세 요소로 구성됩니다.

```text
State   → 원본 데이터
Getter  → 계산된 데이터
Action  → 데이터를 변경하는 함수
```

# 8. `src/assets`

Vite가 빌드 과정에서 처리하고 최적화할 자원을 저장합니다.

```text
assets/
├── images/
│   ├── logo.png
│   └── background.jpg
├── styles/
│   ├── reset.css
│   └── variables.css
└── fonts/
```

컴포넌트에서 다음처럼 가져옵니다.

```vue
<script setup>
import logoUrl from '@/assets/images/logo.png'
</script>

<template>
  <img :src="logoUrl" alt="로고" />
</template>
```

`@`는 보통 `src` 폴더를 의미합니다.

```text
@/components
→ src/components

@/assets
→ src/assets
```

---

# 9. `public`

Vite가 가공하지 않고 **원본 그대로 배포할 정적 파일**을 저장합니다.

```text
public/
├── favicon.ico
├── robots.txt
└── sample-data.json
```

사용할 때는 `/`부터 시작합니다.

```html
<img src="/favicon.ico" alt="아이콘" />
```

## `public`과 `assets` 차이

| 구분 | `public` | `src/assets` |
|---|---|---|
| 빌드 처리 | 하지 않음 | Vite가 처리 |
| 파일명 해시 | 없음 | 생성될 수 있음 |
| import | 보통 하지 않음 | import해서 사용 |
| 용도 | 고정된 정적 파일 | 컴포넌트가 사용하는 이미지·CSS |

일반적인 이미지와 CSS는 `assets`를 우선 사용하고, 반드시 고정된 경로가 필요한 파일만 `public`에 넣는 편이 좋습니다.

# 12. `vite.config.js`

Vite 개발 서버와 빌드 방식을 설정합니다.

```javascript
import { fileURLToPath, URL } from 'node:url'

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],

  resolve: {
    alias: {
      '@': fileURLToPath(
        new URL('./src', import.meta.url),
      ),
    },
  },

  server: {
    port: 5173,
    open: true,
  },

  build: {
    outDir: 'dist',
  },
})
```

주요 설정:

- Vue 플러그인 등록
- `@` 경로 별칭
- 개발 서버 포트
- Proxy
- 빌드 출력 폴더

# 13. `.env`

환경별 설정값을 저장합니다.

```env
VITE_API_URL=https://api.example.com
VITE_APP_NAME=Weather Dashboard
```

Vue에서 사용:

```javascript
const apiUrl = import.meta.env.VITE_API_URL
```

환경별로 나눌 수도 있습니다.

```text
.env
.env.development
.env.staging
.env.production
```

주의할 점은 `VITE_` 환경 변수도 최종 프론트엔드 JavaScript에 포함되므로, 비밀번호나 비공개 API Secret을 저장하면 안 된다는 것입니다.

# 핵심 실행 흐름

```text
1. 브라우저가 index.html을 읽는다.
2. index.html이 src/main.js를 실행한다.
3. main.js가 Vue 앱과 Router, Pinia를 생성한다.
4. App.vue를 #app에 mount한다.
5. Router가 URL에 맞는 View 컴포넌트를 선택한다.
6. View가 필요한 Components를 조립한다.
7. Components는 Props와 Emits로 통신한다.
8. 공통 상태는 Pinia Store에서 가져온다.
9. 서버 데이터는 api 또는 Axios를 통해 가져온다.
```

가장 중요한 구분은 다음입니다.

```text
views      = 페이지
components = 재사용 부품
router     = URL 연결
stores     = 전역 상태
api        = 서버 통신
assets     = 이미지와 스타일
main.js    = 앱 시작
App.vue    = 앱 전체 골격
```
