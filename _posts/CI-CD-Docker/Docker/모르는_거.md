OCI는 **Open Container Initiative**의 약자로, 컨테이너의 공통 표준을 만드는 단체이자 그 표준을 의미합니다.

쉽게 말하면:

```text
Docker가 만든 이미지를
다른 컨테이너 도구에서도
동일하게 실행할 수 있도록 만든 규칙
```

## OCI가 필요한 이유

예전에는 Docker 중심으로 컨테이너 기술이 발전했지만, Docker만의 독점 형식이 되면 다른 도구와 호환하기 어렵습니다.

그래서 컨테이너 이미지와 실행 방법에 관한 공통 규칙을 만들었습니다.

```text
Docker
Podman
containerd
CRI-O
Kubernetes
```

이 도구들이 OCI 표준을 기반으로 동작하기 때문에 서로 호환할 수 있습니다.

## OCI의 주요 표준

### 1. Image Specification

컨테이너 이미지를 어떤 구조로 저장할지 정합니다.

```text
OCI Image
├── index.json
├── manifest
├── config
└── layers
```

레이어는 보통 압축된 tar 파일로 저장됩니다.

```text
Layer 1: Ubuntu 기본 파일
Layer 2: Java 설치
Layer 3: app.jar 추가
```

앞에서 확인한 다음 경로도 OCI 이미지 레이어와 관련 있습니다.

```text
blobs/sha256/4f4fb700...
```

`blobs/sha256/`에는 이미지 설정, manifest, 압축된 파일시스템 레이어 등이 해시값을 이름으로 사용하여 저장됩니다.

### 2. Runtime Specification

컨테이너를 어떻게 실행할지 정합니다.

예를 들면:

- 어떤 프로그램을 실행할지
- 환경변수
- 루트 파일시스템
- CPU와 메모리 제한
- 네임스페이스
- 마운트
- 사용자 권한

개념적인 실행 설정:

```json
{
  "process": {
    "args": ["java", "-jar", "app.jar"],
    "env": ["SPRING_PROFILES_ACTIVE=local-mariadb"]
  },
  "root": {
    "path": "rootfs"
  }
}
```

OCI Runtime Specification을 구현한 대표적인 저수준 런타임이 `runc`입니다.

### 3. Distribution Specification

컨테이너 이미지를 레지스트리에 올리고 내려받는 방법을 정합니다.

```text
docker pull ubuntu:24.04
docker push my-image:1.0
```

Docker Hub, GitHub Container Registry 같은 레지스트리와 통신하는 규칙입니다.

## Docker 실행 흐름과 OCI

```bash
docker run ubuntu:24.04
```

내부적으로 단순화하면:

```text
Docker CLI
    ↓
Docker Engine
    ↓
containerd
    ↓
runc
    ↓
Linux 커널
```

각 역할:

- Docker CLI: 사용자가 명령 입력
- Docker Engine: 이미지, 컨테이너, 네트워크 관리
- containerd: 이미지와 컨테이너 생명주기 관리
- runc: OCI 실행 설정에 따라 실제 컨테이너 생성
- Linux 커널: namespace, cgroup, OverlayFS 제공

## OCI와 OverlayFS 관계

둘은 같은 것이 아닙니다.

```text
OCI
→ 이미지 구조와 컨테이너 실행 방법에 대한 표준

OverlayFS
→ 이미지 레이어를 합쳐서 파일시스템으로 보여주는 기술
```

OCI 이미지에는 여러 파일시스템 레이어가 들어 있습니다.

```text
OCI 이미지 레이어
    ↓
Docker가 OverlayFS로 결합
    ↓
컨테이너의 / 파일시스템
```

## 한 문장으로 정리

```text
OCI는 컨테이너 이미지와 실행 방식을 여러 도구가 공통으로 사용할 수 있도록 정의한 표준이다.
```

그래서 Docker로 만든 OCI 호환 이미지를 containerd, Podman, Kubernetes 같은 다른 컨테이너 환경에서도 실행할 수 있습니다.
